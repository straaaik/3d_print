# Этап 5 — заказ, snapshot, резерв и производство

Основа: gate этапов 1–4 пройден, DECISIONS_AND_CONSTRAINTS и 05_PHASE_ORDERS / TASK_02, TASK_04, TASK_06 обязательны. Рабочая ветка codex/business-modernization; E2E только перед общим final push.

1. Расширить цельный state/outbox новым order lifecycle command. Head и snapshots позиций сохраняются вместе; расход материала выполняется только на первом достижении Печать/поздних статусов. При создании резервировать доступный finished stock по текущему basis, недостающее сохранить как remaining. Перед печатью добрать новый stock, произвести только остаток. Рецепт frozen, цена материала для нового производства текущая. Manual позиции без catalog ID также могут производиться по frozen recipe.
2. Отделить редактирование head/payment от явного редактирования расчётных позиций. Finance/status Save никогда не перечитывает текущий product. После производства recipe/количество защищены; отмена/архив сохраняет события, не возвращает материал. Возврат годных изделий только отдельной командой, с ограничением количества и исходной фактической стоимостью. До производства отмена освобождает только фактический резерв. Revision защищает от stale editor.
3. Подключить API/DataProvider/projection и legacy compatibility к этому слою. Удалить блокировку shortage из UI/API/SQL. Старые заказы сохраняют исторический cost/snapshot; миграция не производит их молча. Order head сохраняет agreed_price, payment0/payments[]; expense остаётся совместим.
4. Общая модалка поддерживает manual multi-item calculation drafts, полный ProductCalculationEditor/CalculationReceipt для каждой детали и общий чек. Новые items используют общее ядро. NumberInput на финансовых/числовых полях. Физические quantities/deficit видны в drawer/modal. Таблица, сортировка, KPI/Stats используют calculateOrderFinancials payment-cost; planned отдельно.
5. Additive migration, exact schema block, MIGRATIONS; owner lock, CAS, receipt-before-validation, атомарный head+items+inventory, ограничения неизменяемого аудита. Проверить локально два применения и rollback/retry/owner isolation.
6. Unit сценарии stock2/order5 → +1 stock → direct Готово, повтор переходов, material deficit, cancellation/return, immutable old snapshots, stale editing, payments0/50/100/120. Typecheck/lint/build, SQL и browser smoke; завершить gate до этапа6.

Ruling: физически учтённое количество хранится отдельно от оценочной стоимости ещё не произведённого остатка. Head cost включает фактическую стоимость готовых/произведённых единиц и frozen estimate оставшихся; после первого производственного порога полностью фактический. Отдельный order revision и мягкое архивирование сохраняют parent IDs/audit. Legacy завершённые заказы не инициируют задним числом производство при финансовом редактировании.
