## 1. Обзор и цели

Цель задачи — полностью унифицировать отображение сборных изделий (сборок) с коллекциями в каталоге товаров (`ProductsV2Table`), а также расширить состав сборок новой категорией компонентов: **Электроника**.

### Ключевые требования:
1. При раскрытии сборки в таблице её компоненты разворачиваются **полноценными строками таблицы**, выровненными по общей сетке колонок (артикул, наименование, материал/тип, вес/время, количество, себестоимость, цена, прибыль, маржа), в точности как варианты внутри коллекций.
2. Состав сборки разделяется на 3 логические группы с древовидной связью (`┌─` и `└─`):
   * **Печатные детали** (3D-печать: материал, вес, время печати, количество, себестоимость, цена).
   * **Крепёж и фурнитура** (метизы: винты, гайки, втулки, магниты, подшипники).
   * **Электроника и компоненты** *(новое)* (платы, моторы, датчики, светодиоды, выключатели, провода).
3. Внизу раскрытой сборки выводится компактная панель сводки и действий в стиле Cockpit Console (`[Создать заказ]`, `[В калькулятор]`, `[Редактировать состав]`, учет труда мастера, общая себестоимость, итоговая цена, прибыль и маржа).
4. Все анимации раскрытия и переходов выполняются строго через библиотеку `motion` (`motion/react`).
5. В модальном окне редактирования сборок (`AssemblyModal`) появляется блок управления электроникой (добавление, количество, себестоимость, цена).
6. В базу данных Supabase добавляется колонка `assembly_electronics jsonb` с мгновенным fallback на `localStorage`.

## 2. Модель данных и типы

### 2.2. Расширение движка формул (`src/shared/lib/formulas.ts` & `src/widgets/ProductsList/helpers.ts`)

В `AssemblyTotalsResult` добавляются поля:
* `electronicsBaseCost: number` — сумма (cost_per_unit * quantity)
* `electronicsFinalPrice: number` — сумма (price_per_unit * quantity)
* `totalElectronicsPieces: number` — общее число компонентов электроники

В функции `calculateAssemblyTotals(parts, hardware, assemblyLaborMinutes, laborRate, isOwnerLabor, electronics)`:
* `grandBaseCost = partsBaseCost + hwBaseCost + electronicsBaseCost + effectiveLaborBaseCost`
* `grandFinalPrice = partsFinalPrice + hwFinalPrice + electronicsFinalPrice + (isOwnerLabor ? 0 : laborCost)`
* Прибыль и маржа рассчитываются от полных сумм.

В функции `prepareDraftOrderFromProduct(item)`:
* Добавляется статья расхода сметы:
  ```ts
  if (electronicsCost > 0) {
    cost_items.push({
      category: 'Электроника и компоненты',
      amount: Math.round(electronicsCost * orderQty * 100) / 100,
      note: `${electronics.length} поз. электроники`,
    });
  }
  ```

## 3. Отображение в каталоге (`ProductsV2Table`)

### 3.1. Структура раскрытой сборки
При клике на стрелку раскрытия сборки (`onToggleExpand`) в таблице последовательно рендерятся:

1. **Разделитель секции «Печатные детали»** (если `parts.length > 0`):
   * Техническая полоса-заголовок, занимающая всю ширину таблицы:
     `┌─ [ПЕЧАТНЫЕ ДЕТАЛИ] · {parts.length} дет. · {totalWeight} г`
   * Строки печатных деталей:
     * Оформлены как строки таблицы со связующим символом `└─` и индикатором цвета сборки.
     * Колонки: Артикул (`#PRT-...`), Тип (`Печать`), Категория (`3D-деталь`), Название, Пластик (с цветным кружком), Вес/Время, Количество (`{qty} шт`), Себестоимость, Наценка, Цена, Прибыль, Маржа, Кнопки действий.
2. **Разделитель секции «Крепёж и фурнитура»** (если `hardware.length > 0`):
   * Техническая полоса-заголовок:
     `┌─ [КРЕПЁЖ И ФУРНИТУРА] · {hardware.length} поз. · {totalHwPieces} шт`
   * Строки крепежа:
     * Связующий символ `└─`.
     * Колонки: Артикул (`#HW-...`), Тип (`Метизы`), Категория (`Фурнитура`), Название, Материал (`Металл / крепеж`), Вес/Время (`—`), Количество (`{qty} шт`), Себестоимость (`{cost * qty} ₽`), Наценка, Цена (`{price * qty} ₽`), Прибыль, Маржа, Действия.
3. **Разделитель секции «Электроника»** (если `electronics.length > 0`):
   * Техническая полоса-заголовок:
     `┌─ [ЭЛЕКТРОНИКА И МОДУЛИ] · {electronics.length} поз. · {totalElPieces} шт`
   * Строки электроники:
     * Связующий символ `└─`.
     * Колонки: Артикул (`#ELC-...`), Тип (`Модуль`), Категория (`Электроника`), Название, Материал (`Электроника`), Вес/Время (`—`), Количество (`{qty} шт`), Себестоимость (`{cost * qty} ₽`), Наценка, Цена (`{price * qty} ₽`), Прибыль, Маржа, Действия.
4. **Панель сводки сборки (Summary Footer)**:
   * Финальная полоса сборки:
     * Слева: Кнопки `<CockpitButton>`: `[Создать заказ]`, `[В калькулятор]`, `[Редактировать состав]`.
     * Справа: техническая телеметрия:
       * Труд мастера: `{laborMins} мин · {laborCost} ₽`
       * Себестоимость: `{baseCost} ₽`
       * Цена: `{finalPrice} ₽`
       * Прибыль: `{profit} ₽ ({marginPercent}%)`

### 3.2. Режимы отображения
* **Подробный режим (13 колонок):** Полная сетка, описанная выше.
* **Компактный режим (9 колонок):** Сдвоенные колонки по образцу Compact Collection rows.
* **Мобильный режим (карточки):** Древовидные блоки внутри карточки сборки с разделителями `┌─` и карточками `└─`.

## 4. Модальное окно сборки (`AssemblyModal`)

1. Добавляются вкладки/секции переключения:
   * `[Печатные детали ({parts.length})]`
   * `[Крепёж ({hardware.length})]`
   * `[Электроника ({electronics.length})]`
2. В секции электроники:
   * Кнопка `[+ Добавить компонент]`.
   * Карточки компонентов: Наименование, Количество (степпер +/-), Себестоимость за шт (₽), Цена продажи за шт (₽), Удаление (`Trash2`).
3. Подвал модалки динамически пересчитывает общую смету с учетом электроники.

## 5. База данных Supabase и локальное хранилище

* **SQL миграция:**
  ```sql
  alter table public.saved_calculations
  add column if not exists assembly_electronics jsonb default '[]'::jsonb;
  ```
* Обновление файла `supabase_schema.sql`.
* Fallback на `localStorage` (`3d_calc_saved_calculations`) для обеспечения работы без задержек.

## 6. План тестирования и верификации

1. **Unit-тесты:**
   * Проверка `calculateAssemblyTotals` с электроникой, крепежом и печатными деталями.
   * Проверка `prepareDraftOrderFromProduct` для сборки с электроникой.
2. **E2E / Браузерная проверка:**
   * Раскрытие сборки в каталоге: проверка наличия разделителей `┌─`, строк `└─`, выравнивания по колонкам.
   * Переключение плотности: подробный (13 колонок) и компактный (9 колонок).
   * Мобильный вид (карточки).
   * Модальное окно `AssemblyModal`: добавление детали, крепежа, электроники, сохранение и проверка пересчета в таблице.
   * Создание заказа из сборки с электроникой.
