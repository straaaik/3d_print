# Задача 2 — прибыль по фактической оплате

В проекте 3D Labs унифицируй финансовую логику заказов. Прочитай AGENTS.md и существующий formulas.ts, Orders, Stats.

Главное правило: основная фактическая прибыль заказа = текущая сумма полученных оплат - фактическая себестоимость заказа.

Примеры:
- Цена заказа 100, себестоимость 60, оплачено 0 => прибыль -60.
- Оплачено 50 => прибыль -10.
- Оплачено 100 => прибыль 40.
- Оплачено 120 => прибыль 60.

Требования:
1. Используй одну централизованную функцию фактической прибыли во всех местах: таблица заказов, строка/карточка/Drawer, модальное окно, сортировка, сводка, статистика/KPI.
2. Статус заказа не должен сам по себе менять прибыль.
3. Новый заказ по умолчанию имеет payment=0 и payments=[]; выбор товара не должен автоматически помечать его полностью оплаченным.
4. Переплата разрешена и увеличивает фактическую прибыль.
5. Основной показатель «Прибыль» в заказах — именно payment - cost.
6. В подробном чеке дополнительно можно показывать справочный показатель «Плановая прибыль» = итоговая цена заказа - себестоимость, но не подменять им фактическую прибыль.
7. Для общей статистики раздели, где это полезно, «объем заказов/начислено» и «получено оплат». Фактическую чистую прибыль считай на основе полученных оплат и себестоимости; существующие отдельные expense-заказы учитывай как расходы согласно текущей модели.
8. Не меняй историческую себестоимость старых заказов при изменении товаров/филамента.
9. Добавь тестовые сценарии для частичной оплаты, нулевой оплаты, полной оплаты и переплаты.

Проверь calculateOrdersSummaryKPI и все места, где сейчас используется amount - cost: они должны быть приведены к новой единой семантике для фактической прибыли.
