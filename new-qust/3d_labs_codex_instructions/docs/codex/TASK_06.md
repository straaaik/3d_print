# Задача 6 — нулевой склад, готовый товар и производственное списание

Исправь складскую логику создания и выполнения заказов в 3D Labs. Недостаток готового товара или филамента не должен блокировать создание заказа.

Готовый товар:
1. Если stock_quantity=0, заказ все равно сохраняется. Покажи неблокирующее уведомление «Товара нет в наличии на складе». Остаток не становится отрицательным.
2. Если на складе 2, а заказали 5: заказ сохраняется; 2 готовых экземпляра резервируются/используются со склада, остаток становится 0, а 3 фиксируются как количество, которое требуется изготовить. Покажи «Недостаточно товара на складе».
3. Храни snapshot по каждой order item: ordered_quantity, quantity_from_stock/reserved, quantity_to_produce/remaining_to_produce и фактически произведенное/учтенное количество. Не пересчитывай прошлое по текущему складу без явной операции.
4. Если после создания заказа пользователь производит +1 товар в каталоге, это отдельная операция «Произвести на склад»: готовый stock +1 и филамент списывается сразу по сохраненному рецепту товара.
5. Перед производственным списанием по заказу система должна снова использовать доступный незарезервированный готовый stock для покрытия оставшейся потребности. Это предотвращает двойной расход, если товар был произведен на склад после создания заказа. После этого филамент списывается только за реально остающееся quantity_to_produce.
6. «+ / Произвести» и «Ручная корректировка склада» должны быть разными операциями. Производство +1 списывает филамент и фиксирует фактическую unit cost новой готовой единицы по текущему расчету; обновляй weighted-average cost basis готового stock без изменения retail/final price товара. Корректировка исправляет учетное количество без производственного расхода и требует/позволяет указать причину. Уменьшение stock не возвращает филамент.
7. Когда заказ забирает готовые единицы со склада, фиксируй их себестоимость в OrderItem из текущего finished-stock cost basis. Единицы, произведенные непосредственно под заказ, фиксируют фактическую производственную себестоимость на момент производства. Общая order cost складывается из этих snapshot-стоимостей и других расходов.
8. Производственный расход заказа срабатывает один раз при первом достижении статуса «Печать» или любого более позднего статуса при перескоке. Если уже списано/произведено — повторные переходы не списывают снова.
9. Если филамента недостаточно для требуемого производства, заказ не блокировать, баланс филамента не делать отрицательным: списать доступное до 0 и зафиксировать дефицит N г с material ID и source/order item. Показать предупреждение.
10. После реальной печати отмена/откат статуса не возвращает использованный пластик автоматически.
11. Сделай ledger готовых товаров и/или минимум аудируемые движения stock: reservation/order fulfillment, production_stock, manual_adjustment, return_to_stock и т.п. Критические Supabase-изменения атомарны и идемпотентны.
12. Удали существующее блокирующее условие не только из UI, но и из save/API/database logic.

Проверь сценарии 0->заказ, 2->заказ5, производство +1 после заказа, прямой переход в «Готово», повторное переключение статусов и нехватку филамента.
